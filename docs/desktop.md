# 使用 ICEPick 桌面 App

ICEPick 打开后直接进入聊天。日常使用只需连接模型、发消息；不需要配置 Agent、运行 ID 或工作流程。

## 本机数据位置

所有应用数据统一放在二进制旁的 `data/`：配置 `config.json`、数据库 `icepick.db`、密钥 `credentials.json`、日志 `icepick.log`、Skills 目录、宿主锁/IPC 文件、命令临时目录 `exec-tmp/`。Linux 的页面存储与 WebView 缓存位于 `data/webview/`，Windows 的 WebView2 数据目录也指向这里。使用本项目默认构建位置时即 `bin/data/`。从别的目录启动不会改变数据位置；AppImage 使用安装的 `.AppImage` 文件旁的目录。应用需放在可写位置，无法写入时会明确报错。更换二进制所在目录时，需要一起移动 `data/` 才能继续使用原有数据。

## 第一次使用

1. 点击“连接模型”，选择服务商。本机可用 Ollama / LM Studio；远端填写服务商提供的密钥和模型名称。自定义地址在单独展开项里填写。
2. 点击“保存并连接”，连接成功后返回聊天。密钥单独保存在本机，不写入聊天、助手分享包或运行日志。
3. 输入问题，按 Enter 发送，Shift+Enter 换行；中文输入法选词时的 Enter 不发送消息。
4. 发送到远端前，会显示实际接收地址和资料类别。只有明确允许后才继续；拒绝会保留输入，不发送内容。自定义代理按真实地址提示，不假装内容仍只交给原服务商。

## 聊天和资料

- 侧栏“新对话”从任何页面立即返回聊天并显示创建进度；失败时在聊天页提示重试。顶部选择器只改变当前对话后续使用的助手。助手管理里的编辑选择不影响当前聊天。选择“使用这个助手开始新对话”可直接启用编辑好的助手；聊天顶部的“添加或管理助手…”可打开助手管理。
- 消息按 Markdown 显示，支持标题、列表、表格和代码块；回复和代码可复制。不会执行回复里的原始 HTML；外部 Markdown 图片提供点击查看，避免悄悄加载远端图片。
- 输出在同一聊天滚动区显示。位于底部时跟随输出；向上查看时保留阅读位置，可点“回到最新消息”。较早历史按页加载，普通聊天不展示工具原始消息。
- 可以选择文件、拖拽文件或粘贴图片；图片显示缩略图。历史附件可预览和另存。DOCX 当前保留提取正文，下载为文本，不能还原原始文档版式。
- “选择文件夹”打开系统选择器，再明确确认此对话的访问范围。选择器本身不授予权限，命令与具体文件操作继续检查。文件夹选择用于新任务，不能扩大旧任务已冻结的权限。
- 粘贴网页链接后，开启已有“联网”开关即可请求读取。当前模型不支持联网时，发送会提供“关闭联网并发送”的明确选择；不会把普通聊天锁死或静默忽略联网要求。
- 切换对话时保留各自未发送文字和选中的文件；文字同时保存在当前窗口的会话存储中。附件草稿目前仅保留在该 App 页面运行期间，关闭或重新加载页面后需重新选择文件。
- 对话自动从第一条用户消息命名，可搜索标题、重命名和删除。删除前有确认，运行中或结果未知时不允许直接删除；关联子任务记录一并清理，共享记忆和助手配置不删除。包含已采用助手/工作方法建议的对话会保留来源，需先撤销相关建议才能删除；未采用的建议随对话删除。

## 操作确认与恢复

必要操作会说明“读取/写入哪个文件”“执行什么命令”，而非要求理解工具名称。协作任务的待确认操作也汇总到主聊天。

对中断后无法确定的操作，先检查对应文件或服务，再记录实际情况。可以选择“暂不确定”继续保留，ICEPick 不会自动重放可能已生效的操作。结果与核对依据仍保存在原有审计记录中。

固定流程要求补充信息时，在输入区补充后点“继续处理”，沿用原有进度。需要从头开始时会提醒可能重复此前的修改。运行细节、检查与回顾入口位于“任务详情”；运行 ID、预算、指纹和原始记录在其开发者记录内。

## 助手与设置

- “助手”提供日常、写作、研究、开发模板及空白创建。模板卡片明确表示“添加并编辑”，就地显示进度和结果；失败时可直接重试，有未保存修改时先确认保留再创建。普通编辑层提供名称、用途、工作说明、记忆偏好以及 Skill/MCP 启用配置；工具限制、组件、固定阶段和模型覆盖配置统一放在“设置 → 开发者设置”。助手页的“配置模型覆盖与工作流程”跳转到同一入口，两页共用草稿。研究/开发保留试用提示，不宣称真实模型质量已经稳定验收。
- 模型密钥统一在“设置 → 模型连接”管理。上方选择服务商可替换密钥，下方展开“管理已保存的密钥”可删除；开发者设置不再有另一套入口。“检测已保存的连接”不会保存当前表单草稿。
- 权限与记忆页进入时刷新已授予的权限；保存偏好只修改本次编辑的字段，避免覆盖聊天中新允许的文件夹。同一字段发生冲突会拒绝覆盖并提示核对。
- 助手编辑草稿在切换页面、切换编辑对象和刷新列表时保留；存在未保存内容时提示。导出要求先保存，恢复默认前需要确认。
- AI 可以根据自然语言创建/改进助手或工作方法。证据从实际工作列表选择，不要求复制 Run ID；任务详情也可直接发起“根据这次工作改进助手”。普通候选可通过表单修改，完整 JSON 仍可在开发者设置编辑。
- 候选仍需手动采用，尚不自动评估或自动发布。新增工作方法可以明确选择用于正在编辑的助手，不覆盖共享来源。
- “设置 / 模型连接”完成模型、密钥和连接检测；“权限与记忆”管理当前对话的确认策略、授权与记忆；“开发者设置”保留精细权限、原始服务与运行配置。普通流程不需要编辑配置文件。
- 错误优先给出解释和可行下一步，原始原因放在可展开的技术详情中。

## 开发验证与限制

`frontend/e2e/product.mjs` 通过真实 React 页面、Chromium 和模拟 Wails 绑定检查首次启动、统一模型接入、草稿、文件选择/拖拽/粘贴预览、Markdown、输入法、联网恢复、具体目的地授权、文件夹确认、子任务审批、助手保存、对话管理及窄窗口布局。可在 frontend 目录运行 npm 的 test:ui 脚本；需要本机 Chromium，所有测试产物放工作区 .cache。

后端测试检查实际来源/目标预览不创建任务或自动授权、附件内容读取、分页顺序、对话删除的事务与共享上下文保留、中断/未知结果阻止删除。真实模型兼容、系统原生文件夹弹框的人工验收和干净环境安装仍按 R7 单独跟踪；模拟验证不等同于这些验收已经完成。
