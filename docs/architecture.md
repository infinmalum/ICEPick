# ICEPick 设计文档

状态：目标设计，2026-10-03。实现进度见 [实施计划](../IMPLEMENTATION_PLAN.md)。本文描述目标行为；除“当前实现”一节外，不表示功能已经交付。

## 1. 产品边界

ICEPick 是本地优先、领域无关的 Agent 宿主。使用一个默认运行循环，通过模型适配、MCP 和 Skills 接入能力；上下文、记忆与客户端按实际需要分模块实现；桌面与 CLI 使用同一套宿主契约。用户从空白模板创建 Profile，分别编辑人格、提示词、模型和能力；Agent 引用 Profile 并持有独立会话、记忆和本机授权。

“一切皆插件”体现为能力可组合、可启用和替换，扩展优先兼容现有生态：工具用 [MCP](https://modelcontextprotocol.io/)，可复用指令用 [Agent Skills](https://agentskills.io/specification)，独立 Agent 互联用可选的 [A2A](https://a2aproject.github.io/A2A/latest/specification/)。模型按提供方协议适配。ICEPick 不建设通用插件加载器、自有插件包格式、插件市场或通用依赖解析系统，这些不属于后续待办。运行循环、存储和策略使用普通内部模块与必要接口组织，由应用随版本交付；内部接口不构成面向第三方的插件 SDK。

简洁性约束：当前只实现一个循环和 SQLite 存储，不提供运行驱动/数据库选择器；接口仅服务已存在的调用边界和测试。可选能力按需交付，不要求核心预设全部扩展点。新增抽象须有当前消费者，新增配置须有用户实际选择需求。核心版交付对话循环、模型与标准能力接入、会话恢复、权限审批、桌面/CLI 和上下文预算/压缩；长期记忆、Plan、委派、分享、Jev 与 A2A 分别作为后续增量，不阻塞核心版发布。

### 不变量

1. **模板用于创建 Profile**：内置一个空白模板和一个简洁默认 Profile，不预置多种职业角色。用户可创建、编辑、复制及导入任意 Profile。
2. **Profile 与 Agent 分离**：Profile 是可复用配置组合，各组成部分独立保存；Agent 有稳定 `agent_id` 和当前 `profile_id`。多个 Agent 可引用同一 Profile，一个 Agent 可切换 Profile。
3. **状态和授权属于 Agent**：会话、记忆、任务及本机授权不属于 Profile；引用或切换 Profile 不复制、不清空也不共享这些数据。
4. **安全边界由宿主执行**：提示词、Skill、MCP 工具描述、扩展内容和 Jev 判断都不能授予权限或替用户批准操作。实际工具范围取 Profile 能力选择与 Agent 本机授权的交集。
5. **运行使用快照**：每次 Run 记录 Agent ID、Profile ID、生效修订和解析后的完整配置快照；Profile 编辑或切换影响后续 Run，权限收紧对在途 Run 立即生效。
6. **可选能力独立开关**：Profile 可保存记忆、压缩、委派与 Jev 使用偏好；实际访问仍受 Agent 授权控制。A2A 入站发布与认证按 Agent 在本机配置，切换 Profile 不自动公开服务。
7. **Profile 可分享**：导出、导入及复制只处理可复用配置，不携带 Agent 身份、会话、记忆、密钥或本机授权。导入创建新 Profile，用户再选择用于已有或新建 Agent。
8. **目录共享，状态隔离**：MCP 与 Skills 由应用统一发现，Profile 选择全部、指定项目或都不启用；运行按 Agent 授权复核。引用同一 Profile 的 Agent 仍各有会话和记忆。
9. **数据外发单独授权**：工具可用范围和网络工具权限不代表上下文可发送到远端模型、Jev 或 A2A。每次外发前按实际目的地与待发送内容检查数据策略；收紧立即生效。
10. **共享运行必须有唯一所有者**：同一会话的活跃任务、审批及相关 MCP 进程只能由一个运行宿主持有；桌面与 CLI 通过本机 IPC 访问该宿主。首版可每用户配置一个宿主，但不把全局单实例写成永久架构限制。
11. **副作用调用不盲目重放**：外部副作用工具进入执行态后若失去结果，恢复为 `execution_unknown`，不得自动重试。
12. **执行边界**：宿主进程执行随应用交付的代码，不提供第三方代码加载入口；外部 MCP 进程按单独的进程边界管理。Skill 正文是数据，不因安装而执行代码或获得权限。

## 2. 组件与数据流

```text
桌面 UI ─┐
         ├─ 本机 IPC ─ 运行宿主（身份、生命周期、事件、安全关口）
CLI ─────┘                  │
                            ├─ Profile 与 Agent 实例
                            ├─ 本机策略与授权
                            ├─ 运行循环：内置 ReAct
                            ├─ 模型适配：本地 / OpenAI / Anthropic / Gemini 等
                            ├─ 工具来源：内置能力 / MCP 服务
                            ├─ 指令来源：Agent Skills
                            ├─ 可选能力：记忆 / 压缩 / 委派 / Jev / A2A
                            └─ 持久化：SQLite
```

运行核心输出统一事件，例如 `run_started`、`message_delta`、`message_completed`、`tool_requested`、`approval_required`、`tool_finished`、`subagent_started`、`run_finished`。`message_delta` 实时广播并在宿主内存中合并；`message_completed` 保存完整消息。工具、审批、委派及运行终态等状态转移必须及时持久化，不能把每个 token 都当作一条 SQLite 事件。桌面与 CLI 订阅同一事件流，重连时读取持久状态及宿主内存中的未完成文本。宿主崩溃可丢失尚未完成的文本，界面标记中断；首版不实现文本检查点。流式文本已实现：适配器逐片段广播，宿主内存合并后完整落盘。

应用服务向两种入口提供相同操作：列出/创建/复制/更新 Profile 及其独立组成部分，创建/重命名 Agent、选择或切换其 Profile，创建/继续会话，开始/取消运行，列出待审批调用，批准/拒绝调用，读取运行事件。入口不得直接调用 MCP Hub 或绕开应用服务写数据库。MCP 服务连接由应用管理；Profile 的能力选择只引用服务及允许的工具，实际调用仍受本机策略控制。

| 层级 | 用户可自定义内容 | 统一负责的部分 |
|---|---|---|
| 应用 | 模型连接、MCP 服务、Skills 目录、Jev 连接、A2A 总开关及监听地址 | 资源发现、凭据保存、服务生命周期 |
| Profile | 人格引用、提示词组合、模型绑定、工具与 Skills 选择、记忆/压缩/委派偏好 | 可复用配置、编辑修订与运行快照 |
| Agent | 实例名称、当前 Profile、会话与记忆管理 | 稳定身份、状态归属 |
| 本机策略 | 工具与数据范围、审批、外发目的地、A2A 入站/出站授权 | 授权记录、执行时复核与即时撤权 |
| 运行 | 会话、任务材料、用户批准或拒绝、取消 | 生命周期、预算上限、最终策略复核、事件契约与持久事实 |

应用层加入新资源不改变其他 Profile 的显式选择。“全部”只覆盖已安装并经用户信任确认的资源；用户主动安装或编辑与第三方升级分别处理：发现资源不自动安装或执行；第三方程序、可执行依赖及影响风险的 schema 变更需重新评估。用户编辑 Skill 文本不要求逐次重新授权，正文加载不执行脚本。用户可在任意时刻把“全部”改成指定列表。可配置的模型端点不等于任意协议都已兼容；缺少适配器时应明确标为不支持。

### 标准接入与内部模块

MCP 负责服务连接、工具发现与调用；Skills 负责标准目录发现、元数据和指令资源加载；A2A 按其阶段接入远端 Agent。分别实现对应适配器，不强制套入统一的 ICEPick 插件清单。各标准的兼容范围及未支持项明确记录，不能把支持一个标准说成支持所有扩展格式。

内部模块根据真实调用关系定义少量接口，例如模型请求、工具执行、会话存储和上下文来源。应用显式创建与连接这些模块；人格和 Skill 可提供提示词内容，工具来源可合并到统一目录。组合顺序、重名冲突及缺失资源由具体模块处理，无需通用插件注册中心、动态装载或依赖图管理。

应用级连接与目录可共享，Profile 级能力选择独立，Run 保存一致的定义快照。停用 MCP 服务或修改资源时，明确处理在途调用与进程清理，不静默替换运行依赖。模型请求、工具调用和外发统一经过权限、审批与数据检查；内部模块不能自行跳过这些入口。存储实现须满足持久化、写入所有权与恢复语义，SQLite 为当前实现目标。

外部 MCP 进程的系统访问能力取决于进程权限与隔离措施，Go 接口和单次工具参数检查不能代替进程隔离。模板或 Skill 中的依赖声明不触发自动安装、执行或授权。

### 模型协议边界

运行宿主提供统一的内部消息、工具调用、流式事件、用量和错误表示；模型适配器负责各服务的请求/响应转换。Ollama 与 LM Studio 使用本地 OpenAI Chat Completions 兼容接口；OpenAI 官方接口、Anthropic Messages 和 Gemini generateContent 分别作为明确的适配目标。仅使用 OpenAI 风格 JSON 不代表已兼容 OpenAI 官方服务，更不代表兼容 Anthropic 或 Gemini。OpenAI Responses 等与 Chat Completions 不同的接口需单独评估。

接入官方服务时优先使用各家的官方 Go SDK：OpenAI `openai-go`、Anthropic `anthropic-sdk-go`、Google `go-genai`。SDK 只负责该提供方的传输、类型与协议；ICEPick 自己保留消息归一化、工具权限、审批、工具执行、会话与压缩控制，不启用 SDK 的自动工具运行循环。Ollama、LM Studio 和其他仅声称 OpenAI 兼容的端点继续走独立的兼容适配器，并用协议测试验证差异。锁定 SDK 版本并检查其 Go 版本要求。

每个适配器至少验证文本多轮、系统指令、工具定义与调用结果回填、流式输出、取消、用量和错误处理；模型不支持某项能力时，应在配置或运行时明确提示。模型发现可以使用提供方接口或手动输入模型 ID。远端地址、凭据引用和本机默认值分开管理；密钥不进入普通 Agent 配置、会话或日志，切换模型不改变 Agent 的工具权限，也不能绕过数据外发策略。

### 数据外发边界

数据外发策略独立于工具权限、审批模式和模型凭据。内容至少标记来源（用户输入、文件、记忆、Skill 正文、工具结果、子任务输出、系统提示词及其摘要），并按实际数据范围标记为公开、工作区、个人、凭据或未知。摘要、转述和子任务输出保守继承参与输入的来源限制并集；未知来源需明确授权或仅本地处理。首版为当前会话上下文累计保存来源范围及允许目的地的交集，派生内容沿用更严格的限制；不建设逐片段依赖图，不承诺逐字溯源或自动发现所有秘密。策略按目的地配置：`local_only`、允许远端模型、允许指定提供方，以及永不远端发送的敏感数据。Jev、A2A 和其他远端端点分别受同一外发检查，不因为它们不是“模型”而豁免。

内核在组装每一次远端请求后、传输前检查实际 payload 与具体目标端点，不能仅凭提供方名称授权；禁止的片段不得发送，必要时要求用户调整范围或改用本地模型。配置远端模型或持有 API 密钥不等于授权外发；默认 Agent 初始只允许本地处理，用户明确启用远端目的地及数据范围后才可发送。用户可按目的地和数据范围持续授权，界面展示当前发送目标，无须每条消息重复审批。数据外发策略收紧立即影响下一次发送，包括已开始运行的任务；已发送的数据无法撤回。收紧后若现有上下文不再获准，暂停该目的地的发送；用户可切换获准模型，或以明确允许的材料新建会话。首版不自动删改历史、脱敏或重建摘要以继续外发。日志只记录目的地、来源类别、决策与必要摘要，不复制敏感 payload。

### 默认 ReAct 驱动的一次任务

1. 选择 Agent 和会话，解析所选 Profile 的一致快照，并加载当前本机策略；会话必须属于这个 Agent。
2. 组装系统提示词、已获准的 Skill 元数据、该会话的摘要与最近消息，以及该 Agent 可用的 MCP 工具定义；发送前按实际 payload 和目的地执行数据外发检查。
3. 模型回答或请求工具/子 Agent。所有请求先经过策略网关，再按审批模式执行、等待或拒绝；拒绝结果也返回模型。
4. 工具结果和审批事件写入运行记录；模型继续，直到完成、取消、失败或达到预算。
5. 上下文接近阈值时压缩旧消息；摘要只影响后续发送给模型的上下文，不改写原始消息。

Plan 是同一循环上的可选协作能力：记录规划状态、贡献指令并提供计划审核入口，不要求另建执行引擎。权限与审批独立执行；“仅规划不修改”必须由工具策略落实。

宿主用确定性代码执行权限、预算、schema 和路径检查；默认驱动让 Agent 在正常模型推理中决定下一步。仅对已登记、确实需要独立结构化判断的有限候选选择、评分或真假问题调用判断服务。可合并的判断不拆成多次模型请求；Jev 关闭时使用当前 Agent 的 LLM。生成任务说明、工具参数、摘要和最终回答仍由生成式模型完成。

## 3. 空白模板、Profile 与 Agent

空白模板是创建 Profile 的起点，不是运行实例。应用只内置一个简洁默认 Profile：简短通用助手指令、用户默认模型及 MCP/Skills 能力选择，不预装职业角色、工作流或独立规划器。默认 Profile 初始选择全部已安装且经确认的能力；这仅决定候选工具，不授予访问权限。用户可从空白模板创建 Profile，也可复制、编辑或导入已有 Profile。

| 对象 | 内容与归属 |
|---|---|
| 空白模板 | 无人格、任务指令或能力选择；用于新建 Profile |
| Profile | 稳定 `profile_id`、名称、编辑修订及各组成部分引用 |
| 人格、提示词、模型绑定、能力选择 | 分别保存和编辑，由 Profile 组合；模型绑定不保存密钥 |
| Agent | 稳定 `agent_id`、实例名称、当前 `profile_id`；可创建多个实例引用同一 Profile |
| 本机策略 | 按 `agent_id` 保存工具范围、审批、外发、记忆访问及 A2A 授权 |
| 会话、记忆与运行 | 按 `agent_id` 归属；Run 额外记录使用的 Profile 及快照 |

Profile 的各部分保存在分开的文件或表中，不塞回一份权威大型 JSON。组合编辑以事务或等效步骤发布一致修订；运行读取解析后的不可变快照。无需组件版本仓库、Profile 继承、Agent 局部配置覆盖或多层合并规则。

### 创建、编辑与切换

- 首次启动创建一个默认 Profile 和引用它的默认 Agent。默认 Agent 的本机策略单独初始化为半自动、一般资源范围不限、远端外发关闭；敏感来源继续受保护。其他新 Agent 单独初始化授权，选择已有 Profile 不复制其他 Agent 的授权。
- 同一 Agent 可随时选择另一个 Profile，下一次启动的 Run 使用当时选中的最新已提交配置；已经开始的 Run 保持快照，包括等待审批的 Run。切换选择与启动 Run 由宿主顺序处理。界面区分“当前运行使用”和“下一次使用”。
- 切换保留该 Agent 的会话、记忆和本机策略。新 Profile 关闭记忆时后续 Run 不检索或写入，已有记忆保留。切换不会忘记历史；新建会话取得新上下文，新建 Agent 取得独立会话与记忆。
- 多个 Agent 引用同一 Profile 时，编辑会影响它们后续的 Run；编辑界面显示引用关系。希望独立修改时先复制 Profile，再为目标 Agent 选择副本。
- 复制 Profile 为其自有人格、提示词等生成独立副本，共享已安装 MCP/Skills 仅复制引用；不复制运行状态、密钥或授权。恢复默认只重置选定的 Profile 内容，并遵循同样的后续 Run 生效规则。
- 切换或编辑不能扩大本机授权；实际能力取运行快照与当前 Agent 策略的交集。权限及外发收紧即时复核，放宽只作用于新 Run。切到远端模型时，已有历史、摘要和记忆仍须通过外发检查。
- 被 Agent 引用的 Profile 删除前须先让用户为这些 Agent 另选 Profile，不静默回退。删除 Agent 不删除共享 Profile；按原有规则处理该实例的会话和记忆。历史 Run 的快照不依赖 Profile 继续存在。

### 持久数据

SQLite 中的有序消息、工具调用及审批状态是持久事实；关联变更在同一事务提交，提交后通知客户端。事件用于订阅和恢复定位，不另建独立事件溯源系统。Step 使用 Run 内序号，摘要和界面状态由事实派生。

| 数据 | 关键关联与用途 |
|---|---|
| `profiles` 与独立配置内容 | Profile 身份、组合引用和编辑修订；无授权和运行状态 |
| `agents` | 实例身份、名称和当前 `profile_id` |
| `agent_policies` | 按 `agent_id` 保存本机策略，切换 Profile 不改写授权 |
| `sessions`、`messages` | 会话属于 Agent，消息属于会话，保留有序结构化历史 |
| `runs`、`run_events`、`tool_calls` | 记录 `agent_id`、`profile_id`、Profile 修订/解析快照、父 Run、工具请求及结果 |
| `approvals` | 绑定具体 Run、工具调用与参数，不能因切换 Profile 转移或复用 |
| `memories`、`context_summaries` | 按 `agent_id` 隔离；摘要另记会话和覆盖区间，不按 Profile 共享 |

查询和约束按 Agent 身份隔离数据。迁移现有单体 `AgentProfile` 时，每条旧记录生成一个 Profile 与一个 Agent，保留原 `agent_id`、会话归属及已有本机策略；不因内容相似自动合并 Profile。新建 Agent 的授权初始化与旧数据迁移区别处理。

## 4. 工具、权限与审批

工具由宿主的工具来源接口汇集；外部工具优先通过 MCP 接入，少量内置能力也走同一调用与策略关口。Profile 可选择全部已信任的服务，也可只选择指定服务；可选工具白名单进一步缩小可见集合。Skills 由独立指令来源发现，按 Profile 选择、运行时按 Agent 授权复核；现有 MCP `load_skill` 可继续作为正文加载入口。MCP 的 schema、注释和描述用于协议与展示；工具风险及可访问范围由 ICEPick 的本地策略登记，模型输出的工具名和参数在每次调用前重新校验。

工具风险至少记录两个维度：`effect` 为 `pure / read / write / execute / external / unknown`（网络和外部副作用归入 `external`），`sensitivity` 为 `public / workspace / personal / credential / unknown`。敏感度依据实际目标路径、资源和返回数据复核，不能只相信工具名称或 MCP 描述。默认保护凭据目录、环境密钥和其他已知敏感来源；无法确认数据范围的读取视为未知。审批不能替代范围授权，未知工具即使获得人工批准也不能突破明确禁止的目标。对于无法约束内部文件或网络访问的外部 MCP 进程，进程本身按其可见环境和系统权限评估，不能声称单次工具参数校验就限制了它的全部行为。

**权限边界**决定能否使用工具及允许的目标范围，例如工作区路径、命令、网络目标或外部服务；**审批模式**决定已获准的调用是否需要用户确认。未获准的调用在三种模式下都拒绝。

| 模式 | 已获准调用的执行规则 |
|---|---|
| 全人工审批 | 每次工具调用与子 Agent 委派都展示名称、参数和目标，等待用户决定。 |
| 半自动执行 | `pure` 或 `read` 且目标处于明确授权的数据范围内时自动执行；写入、命令、网络、外部副作用、敏感或未知读取均等待确认且仍需满足权限和数据范围。委派按目标权限和任务范围审批。 |
| 全自动执行 | 在 Agent 已获准的工具和范围内执行，不逐次询问；不能越过范围或读取其他 Agent 的状态。 |

审批请求有稳定 ID、超时、取消和持久状态；拒绝或超时作为工具结果返回模型。无交互 CLI 无法获得所需批准时应明确失败或保持待审批状态，不可静默放行。批准应绑定具体工具、参数与目标；参数变化需重新审批。文件和命令工具还要在执行层验证工作区边界、进程取消和输出上限，不能只依赖 UI。

工具调用状态为 `pending → approved → executing → succeeded / failed`，也可进入 `cancelled` 或 `execution_unknown`。在实际调用前持久化 `executing`；外部副作用调用在该状态下发生进程崩溃、连接中断或超时且无法确定结果时，恢复为 `execution_unknown`，不自动重试，也不把它报告成失败。结果未知时暂停相关 Run 的自动推进，防止模型换调用 ID 重复操作；取消或超时不能证明副作用未发生。界面提供核对外部结果和人工处置入口，处置决定单独留痕，不将未知事实改写为成功；只有工具协议支持且验证过幂等键或可查询结果时，才可按该工具的规则安全重试。重试复用持久操作幂等标识，不为每次尝试生成新键。一次批准只对应一次具体调用。

外部 stdio MCP 进程只在完成信任确认且有 Agent 实际使用时启动；首版每个配置的服务在宿主中共享一个连接，首次使用时启动，停用或宿主退出时清理；不引入连接池、自动伸缩或复杂空闲回收。进程使用明确的工作目录、环境变量允许列表、启动与调用超时、进程组清理；不默认继承 ICEPick 的全部环境变量。记录可执行文件指纹、服务版本（若可得）及工具 schema 指纹；二进制或 schema 变化后重新评估风险登记，并暂停依赖旧登记的自动执行，直至重新确认。指纹用于发现变化，不等于对外部进程的沙箱隔离。

## 5. 会话、记忆与上下文压缩

模型历史从有序持久记录重建，包括助手的工具请求、调用 ID、完整参数和匹配结果；展示摘要不能代替这些结构化事实。工具分派前必须确认执行态持久化，写入失败不执行。恢复区分尚未分派与结果未知，补齐明确标注的工具结果，不整批重放。旧记录无法还原时明确标记，不虚构参数。压缩改变模型上下文投影，原始记录保留。

会话、消息、运行、长期记忆、摘要均带 `agent_id`；会话和运行的关联由数据库约束，所有查询按 `agent_id` 与 `session_id` 限定。子任务使用目标 Agent 当前 Profile 的快照，拥有独立任务上下文；默认只使用父任务明确传入的材料，不自动获得目标既有会话或记忆。向父任务返回结果仍须遵守传入材料的来源限制。共享知识库属于将来的显式授权资源，不等同于共享记忆。

长期记忆按 Profile 使用偏好和 Agent 记忆授权共同决定是否开启，并可配置读写方式、保留范围及容量。关闭时不从历史记忆检索，也不从对话自动写入；已有记忆保留到用户明确删除。读写需要当前 Agent 的权限，并在审计中记录来源。复制或分享 Profile 不复制记忆。Skill 内容和工具输出是外部输入，不自动变为可信记忆。

上下文压缩是独立于长期记忆的设置，即使记忆关闭也可用于当前会话。在模型上下文预算接近阈值时，保留系统提示词、当前任务、最近消息和未完成的工具调用；把较早的完整轮次归纳为带来源范围的摘要。摘要按 Agent/会话隔离、可重建，原始消息和工具记录始终保留。压缩失败时保持原上下文并按预算停止或请求用户处理，不能丢弃未完成调用。摘要不是长期记忆，不跨会话自动复用。

## 6. 子 Agent

委派能力交付后可由 Profile 开启，本机允许的目标 Agent 列表按发起 Agent 授权保存。用户设定目标选择方式：指定一个目标，或由模型/Jev 在允许列表中自动选择；当前 Agent 也可列为目标。选择方式只决定委派给哪个 Agent，执行方式相同。每次委派创建独立子任务实例，解析目标 Agent 当前 Profile 的一致快照与该 Agent 本机策略；无需新建 Profile 或持久 Agent。

- 父任务传递明确的任务描述和必要材料；子任务有独立的临时上下文和运行记录，不把工作过程并入目标 Agent 的普通会话。父任务只接收交付结果。
- 子任务默认不访问目标 Agent 的长期记忆；启用目标记忆不等于授权委派读取。首个委派实现仅接受显式传入材料，不提供跨 Agent 记忆授权或候选记忆写入流程；记忆集成有明确需求时再设计。
- 有效权限取父任务许可范围与目标 Agent 自身权限的交集，数据外发也取两者更严格的限制。审批等级为 `auto < semi < manual`，子任务取 `max(parent, target)`；父任务对一次工具调用的批准不继承给子任务的另一次调用。
- 深度、并发、调用次数、令牌/时间预算可配置且有上限；默认深度 1、并发 2。父任务取消时取消所有子任务。
- 子任务记录 `parent_run_id`、目标 `agent_id`、`profile_id` 及其快照、费用/用量与结果；清理临时上下文不删除审计所需的运行记录。

本机委派由内部调度器执行；远端独立 Agent 通过可选 A2A 接入，两者共用审批和权限检查，但保留各自的任务生命周期。

## 7. 可选 Jev 与 A2A

### Jev

[TypeSafe Jev](https://docs.typesafe.ai/primitives) 接受状态与 Choice、Score、Noul 等问题，返回结构化判断。它是已登记结构化判断点的**可选后端**。只有判断结果确实需要独立消费时，才定义统一请求；普通的下一步推理留在 Agent 的模型循环，权限、预算、schema 与路径由内核确定性执行。能从一次推理取得的候选选择不强制增加单独的判断调用。

Jev 实施时先选一个实际需要的结构化判断用例，再定义其输入、结果校验和 LLM 回退。默认使用 Agent 自身模型完成推理；不预设意图分类、Skill 筛选、工具选择、结果复核、记忆评估都需要独立判断服务，也不增加按阶段选择后端的配置矩阵。

应用级连接与 Profile 使用开关分离；关闭时不访问 Jev。请求记录实际后端和错误，外发前检查目的地与数据范围；失败时按用户配置回退到 LLM 或明确报错。后端输出均需校验，任何判断都不能代替权限、预算或人工审批。没有实际调用点时不先建设判断框架。

### A2A

A2A 用于与独立运行的 Agent 系统通信，不替代 MCP 工具、Agent Skills 或本机子 Agent 调度。采用 [A2A 官方规范](https://a2aproject.github.io/A2A/latest/specification/) 的 Agent Card、消息、任务状态与产物；Agent Card 中描述的能力不等同于本地 `SKILL.md` 文件。

应用级 A2A 总开关默认关闭。用户可分别启用客户端与服务端，再为每个本地 Agent 配置出站目标、是否接受入站任务、对外公开的能力描述、认证方式及可传递的数据范围。服务端只发布用户选中的 Agent；创建 Agent 或导入分享包不会自动暴露服务。远端 Agent 由用户添加并查看其 Agent Card 和认证要求。远端结果作为外部输入处理。

入站任务创建属于目标 Agent 的独立运行，经过该 Agent 的权限与审批网关，不获得其他 Agent 的记忆、凭据或会话。出站调用仍按发起 Agent 的网络范围和审批模式处理。A2A 任务的状态、取消、超时和结果映射到本地运行事件；服务不可用时只影响 A2A 功能。

## 8. 桌面与 CLI

桌面和 CLI 共享应用服务契约。一个共享会话同时只有一个运行宿主拥有活跃任务、审批队列和相关 MCP 子进程；其他入口经有本机身份校验的 Unix socket、named pipe 或等效 IPC 调用该宿主，不能为同一会话另起运行驱动或直接改写任务状态。首版可以每用户配置一个宿主，不设计多宿主协调。CLI 首版覆盖 Profile 列表/创建/复制/编辑、Agent 创建/选择/切换 Profile、会话创建/继续、任务执行/取消、审批响应与运行日志。

P1 先落实每个用户数据目录的单一所有权，第二个写入进程拒绝启动；P3c 提取独立运行宿主，桌面与 CLI 均可启动或连接它。首版使用所有权锁，不引入多宿主租约系统；启动时检查数据库并恢复待审批与可恢复任务，进程消失后的副作用调用按结果未知规则处理。IPC 断开不应错误地取消仍由所有者持有的运行。配置修订冲突和同一会话重复运行由所有者统一处理；SQLite 并发读写不是跨进程运行状态共享机制。

## 9. Profile 分享与依赖

Profile 可导出为目录或压缩包，经 GitHub、网盘等渠道分发。包包含模板清单、可分享的人格与提示词定义、模型和能力引用、标准 Skills 文件、MCP/A2A 依赖引用及少量 ICEPick 版本元数据；各组成部分保持独立。发布渠道不是执行协议，分享清单也不是新的通用插件标准。

导出默认排除本机 Agent ID、策略授权、会话、记忆、运行记录、密钥、审批记录和绝对路径。导入创建新 Profile ID，不自动创建 Agent 或更换现有 Agent 的 Profile；用户可选择应用到已有 Agent 或新建 Agent。预览缺失模型、Skills、MCP 服务、A2A 目标及建议的权限和数据外发范围；接收者在本机策略仓库单独决定授权。包中声明的权限、外发、审批、记忆、Jev 与 A2A 开关只是创建建议，不能直接授予本机权限、外发授权或公开入站服务。导入前检查文件路径与大小，不能因读取包就执行其中的程序。

## 10. 当前实现与缺口

已实现桌面与 CLI/IPC、独占宿主、结构化会话历史与重启恢复、工具审批/权限网关、结果未知处置、MCP 与 Skills、Ollama/LM Studio、OpenAI/Anthropic/Gemini 的模型适配与流式输出，以及上下文压缩、逐 Agent 长期记忆与可恢复计划（存储 v10）。压缩为单一默认策略，记忆检索为最近条目注入（无向量检索或多后端），保留策略为手动删除；Plan 未提供“仅规划不修改”模式。真实模型与桌面人工验收仍待记录。

Profile/Agent 已分离。存储 v9 使用 `profiles` 元数据和 `profile_components` 独立配置行，分别保存人格、提示词、模型、能力和运行偏好；事务发布一致修订，只读视图组装 API/Run 快照。Agent 切换 Profile 不影响在途工具选择，实时 Agent 策略仍可收紧限制。默认 Profile 目前支持整组恢复，按组件选择恢复 UI 尚未完成。

MCP 配置只登记命令，Run 首次需要其工具目录时启动所选服务；并发 Run 共享一个连接，宿主退出时清理。外部调用分派后的传输失败进入 `execution_unknown` 并阻断会话继续运行，收到明确工具错误则记录失败；不提供通用自动重试。

外发授权按 Agent 与目的地保存，发送前检查实际请求和持久累计来源，包括自定义提示词、外部工具定义/参数和失败工具输出。本地处理同样累计来源，之后切换远端时仍检查。v9 不自动沿用旧全局授权，原记录保留供核对；旧历史缺少来源时保守标记 unknown。来源分类不等于自动秘密检测，也不约束外部 MCP 自身的网络访问。

尚未实现上下文 token 预算执行与压缩、长期记忆、Plan、子 Agent、Profile 导出/导入、Jev、A2A，以及内置写入/命令/网络工具。相关配置字段不代表能力已交付。详细测试与剩余验收见[实施计划](../IMPLEMENTATION_PLAN.md)。
