# ICEPick 设计文档

状态：目标设计，2026-09-30。实现进度见 [实施计划](../MIGRATION_PLAN.md)。本文描述目标行为；除“当前实现”一节外，不表示功能已经交付。

## 1. 产品边界

ICEPick 是本地优先的桌面 Agent 应用，预留 CLI 入口。一个 Go 运行核心服务多个 Agent；Wails/React 是桌面入口，CLI 是另一入口。用户可连接本地模型，按需配置其他模型与外部服务。机器人平台、Telegram 身份、群管和支付逻辑不属于核心。

设计取向参考 [Pi Agent Core](https://github.com/earendil-works/pi/blob/main/packages/agent/README.md) 对模型、工具循环、消息转换和事件的分层，但 ICEPick 不复制 Pi 的 TypeScript 扩展接口。对外工具使用 [MCP](https://modelcontextprotocol.io/)，可复用任务指令使用 [Agent Skills](https://agentskills.io/specification)。Agent 配置是 ICEPick 的应用数据，不宣称为行业通用 Agent 包格式。

### 不变量

1. **空白模板是唯一基础**：它不预设角色提示词、工具、记忆或子 Agent 权限。Chat、Work 和用户创建的 Agent 都从它生成，没有专用的 Chat/Work 执行引擎。
2. **Agent 可独立编辑**：名称、系统提示词、模型、MCP 工具边界、Skills、权限边界、审批模式、子 Agent 规则和压缩策略可在创建后修改。
3. **配置与状态分开**：复制配置不复制会话、记忆、密钥或授权记录。每个 Agent 有稳定的 `agent_id`。
4. **权限由代码执行**：提示词、Skill、MCP 工具描述和 Jev 的判断都不能授予工具权限，也不能替用户批准操作。
5. **配置与运行留痕**：每次运行记录所用 Agent 配置版本、模型、工具调用、审批和子任务；原始会话不因上下文压缩而丢失。
6. **以用户功能验收迁移**：外部项目可以换用 ICEPick 的运行核心；不要求复刻其源码结构或内部调用顺序。每项功能应明确输入、可见结果、外部依赖和验收用例。

## 2. 组件与数据流

```text
桌面 UI ─┐
         ├─ 应用服务（Agent 管理、会话、审批、运行与事件）
CLI ─────┘       │
                 ├─ Agent 配置仓库（空白模板 → Chat / Work / 自建 Agent）
                 ├─ 运行核心（上下文 → 模型 → 工具/委派 → 结果 → 继续）
                 │    ├─ 模型适配器（Ollama、LM Studio、OpenAI、Gemini、Anthropic）
                 │    ├─ MCP 客户端与工具策略网关
                 │    ├─ Agent Skills 发现与按需读取
                 │    ├─ 子 Agent 调度器
                 │    └─ 可选 Jev 决策适配器
                 └─ SQLite（配置、会话、运行、审批、记忆、摘要）
```

运行核心输出统一事件，例如 `run_started`、`message_delta`、`tool_requested`、`approval_required`、`tool_finished`、`subagent_started`、`run_finished`。桌面端订阅事件并可从数据库恢复状态；CLI 消费同一事件流。流式文本是目标能力，当前实现仍是非流式。

应用服务向两种入口提供相同操作：列出/创建/复制/更新 Agent，创建/继续会话，开始/取消运行，列出待审批调用，批准/拒绝调用，读取运行事件。入口不得直接调用 MCP Hub 或绕开应用服务写数据库。MCP 服务连接由应用管理；Agent 配置只引用服务及允许的工具。

### 模型协议边界

运行核心使用统一的内部消息、工具调用、流式事件、用量和错误表示；模型适配器负责各服务的请求/响应转换。Ollama 与 LM Studio 使用本地 OpenAI Chat Completions 兼容接口；OpenAI 官方接口、Anthropic Messages 和 Gemini generateContent 分别作为明确的适配目标。仅使用 OpenAI 风格 JSON 不代表已兼容 OpenAI 官方服务，更不代表兼容 Anthropic 或 Gemini。OpenAI Responses 等与 Chat Completions 不同的接口需单独评估。

接入官方服务时优先使用各家的官方 Go SDK：OpenAI `openai-go`、Anthropic `anthropic-sdk-go`、Google `go-genai`。SDK 只负责该提供方的传输、类型与协议；ICEPick 自己保留消息归一化、工具权限、审批、工具执行、会话与压缩控制，不启用 SDK 的自动工具运行循环。Ollama、LM Studio 和其他仅声称 OpenAI 兼容的端点继续走独立的兼容适配器，并用协议测试验证差异。锁定 SDK 版本并检查其 Go 版本要求。

每个适配器至少验证文本多轮、系统指令、工具定义与调用结果回填、流式输出、取消、用量和错误处理；模型不支持某项能力时，应在配置或运行时明确提示。模型发现可以使用提供方接口或手动输入模型 ID。远端地址、凭据引用和本机默认值分开管理；密钥不进入普通 Agent 配置、会话或日志，切换模型不改变 Agent 的工具权限。

### 一次任务的路径

1. 选择 Agent 和会话，加载该 Agent 的当前配置版本；会话必须属于这个 Agent。
2. 组装系统提示词、已获准的 Skill 元数据、该会话的摘要与最近消息，以及该 Agent 可用的 MCP 工具定义。
3. 模型回答或请求工具/子 Agent。所有请求先经过策略网关，再按审批模式执行、等待或拒绝；拒绝结果也返回模型。
4. 工具结果和审批事件写入运行记录；模型继续，直到完成、取消、失败或达到预算。
5. 上下文接近阈值时压缩旧消息；摘要只影响后续发送给模型的上下文，不改写原始消息。

## 3. 空白模板与 Agent 配置

空白模板只提供配置字段及安全默认值，不是可运行会话。Chat 和 Work 是首次安装时从该模板创建的两个**普通预设 Agent**。用户可以编辑、复制或恢复它们的出厂配置；恢复不清空已有会话和记忆。用户新建 Agent 时可从空白模板开始，也可复制某个现有 Agent 的配置。复制是一次性快照，源 Agent 之后的修改不会传播到副本。

| 配置项 | 空白模板 | Chat 预设 | Work 预设 |
|---|---|---|---|
| 角色提示词 | 空 | 简短日常助手提示词 | 简短任务助手提示词 |
| 模型 | 待选择；可使用用户默认值 | 用户默认模型 | 用户默认模型 |
| MCP 工具 | 无 | 明确列出的基础只读工具 | 用户已启用且策略登记的工具；新服务需先由用户启用 |
| Skills | 无 | 用户选择 | 用户选择 |
| 审批模式 | 全人工 | 半自动 | 半自动 |
| 子 Agent | 禁用 | 禁用 | 启用，受目标列表和预算限制 |

预设值只在创建或“恢复预设”时应用。所有 Agent 使用同一个运行流程；Chat 和 Work 没有绕过权限网关的特殊代码分支。Agent 配置至少包含 `id`、`name`、`description`、`system_prompt`、`model_ref`、`allowed_tools`、`enabled_skills`、`permission_scope`、`approval_mode`、`delegation_policy`、`context_policy`、`revision` 和时间戳。密钥独立存储，配置仅保存引用。

编辑后增加 `revision`。新任务使用新版本；已开始的任务保持提示词和模型快照。**权限收紧立即生效**：待执行工具和待启动子任务在执行前重新检查当前策略；不再获准的调用被拒绝，已有任务可由用户取消。权限放宽只影响新任务，避免进行中的任务意外获得新增能力。界面应显示运行使用的配置版本。

### 持久数据

| 数据 | 关键关联与用途 |
|---|---|
| `agent_profiles` | `agent_id`、配置 JSON/规范化字段、`revision`、预设来源和更新时间。空白模板作为内置定义管理，不共享用户 Agent 的运行状态。 |
| `sessions`、`messages` | 会话属于一个 `agent_id`；消息属于一个会话，保留原始顺序和内容。 |
| `runs`、`run_events`、`tool_calls` | 运行属于 Agent 和会话；记录配置版本、父任务 ID、工具参数摘要、结果与状态。 |
| `approvals` | 绑定运行、工具调用及参数摘要，记录请求、同意/拒绝/超时和时间。 |
| `memories`、`context_summaries` | 均带 `agent_id`；摘要还带 `session_id` 与覆盖消息范围。 |

从当前数据库升级时，为现有会话创建 Chat 归属并在同一迁移事务中补齐关联。外键和查询条件共同保证隔离；不能仅靠界面筛选。删除 Agent 时先展示会话/记忆数量并提供导出或明确删除路径，不静默把数据转给其他 Agent。

## 4. 工具、权限与审批

工具来自 MCP 服务。应用先列出服务与工具，再由 Agent 配置决定模型可见的工具集合。MCP 的 schema、注释和描述用于协议与展示；工具风险类别及可访问范围由 ICEPick 的本地策略登记，未知工具按最高审批要求处理。模型输出的工具名和参数仍需在每次调用前重新校验。

**权限边界**决定能否使用工具及允许的目标范围，例如工作区路径、命令、网络目标或外部服务；**审批模式**决定已获准的调用是否需要用户确认。未获准的调用在三种模式下都拒绝。

| 模式 | 已获准调用的执行规则 |
|---|---|
| 全人工审批 | 每次工具调用与子 Agent 委派都展示名称、参数和目标，等待用户决定。 |
| 半自动执行 | 已登记的只读低影响调用自动执行；文件写入、命令、网络、外部副作用及未知工具等待确认。委派按其目标权限和任务范围审批。 |
| 全自动执行 | 在 Agent 已获准的工具和范围内执行，不逐次询问；不能越过范围或读取其他 Agent 的状态。 |

审批请求有稳定 ID、超时、取消和持久状态；拒绝或超时作为工具结果返回模型。无交互 CLI 无法获得所需批准时应明确失败或保持待审批状态，不可静默放行。批准应绑定具体工具、参数与目标；参数变化需重新审批。文件和命令工具还要在执行层验证工作区边界、进程取消和输出上限，不能只依赖 UI。

## 5. 会话、记忆与上下文压缩

会话、消息、运行、长期记忆、摘要均带 `agent_id`；会话和运行的关联由数据库约束，所有查询按 `agent_id` 与 `session_id` 限定。子 Agent 使用自己的身份和会话。父 Agent 只传入明确的任务上下文，得到子任务结果，不直接读取子 Agent 的长期记忆。共享知识库属于将来的显式授权资源，不等同于共享记忆。

长期记忆是一项可配置能力：读写需要当前 Agent 的权限，并在审计中记录来源。复制 Agent 不复制记忆；旧机器人记忆只能通过预览后导入到指定 Agent。Skill 内容和工具输出是外部输入，不自动变为可信记忆。

上下文压缩在模型上下文预算接近阈值时触发：保留系统提示词、当前任务、最近消息和未完成的工具调用；把较早的完整轮次归纳为带来源范围的摘要。摘要按 Agent/会话隔离、可重建，原始消息和工具记录始终保留。压缩失败时保持原上下文并按预算停止或请求用户处理，不能丢弃未完成调用。摘要不是长期记忆，不跨会话自动复用。

## 6. Work 与子 Agent

Work 默认开启委派；用户 Agent 可自行开启并配置。子 Agent 是一个独立运行，不是临时复制父 Agent 的记忆。首版只允许选择已存在的 Agent 作为目标，不做自动生成 Agent 或任意递归调度。

- 父任务传递明确的任务描述和必要材料；子 Agent 只得到自己的提示词、记忆和被传入的材料。
- 有效权限取父任务许可范围、目标 Agent 自身权限、当前审批状态的交集；子 Agent 不得提高审批级别或扩大路径、网络、工具范围。
- 深度、并发、调用次数、令牌/时间预算可配置且有上限；默认深度 1、并发 2。父任务取消时取消所有子任务。
- 子任务记录 `parent_run_id`、目标 `agent_id`、配置版本、费用/用量与结果；父任务只接收必要的结果摘要和引用。

以后需要跨进程或远端 Agent 时，再评估标准互操作协议；本机委派无需自造一个对外通信协议。

## 7. 可选 Jev 决策层

[TypeSafe Jev](https://docs.typesafe.ai/llms.txt) 接受状态与 Choice、Score、Noul 等封闭式问题，返回结构化判断和概率；它不替代生成式聊天模型。ICEPick 可选地用它辅助选取子 Agent、筛选候选工具或识别需要复核的低置信判断。它不生成最终回答、不承担上下文压缩，也不能覆盖硬编码权限或代替用户审批。

Jev 默认关闭。接入时使用官方 API 或符合 MCP 的适配服务，不新造插件标准。用户需显式配置服务与凭据，并能看到哪些任务数据将发给外部服务；本地优先模式不依赖 Jev。不可用、超时或低置信时回退到本地规则或交给主模型/用户，而不是扩大执行权限。

## 8. 桌面与 CLI

桌面和 CLI 共享应用服务、配置与数据库，不共享界面实现。CLI 首版覆盖 Agent 列表/创建/编辑、会话创建/继续、任务执行/取消、审批响应与运行日志。命令和 Wails 绑定都调用同一服务接口；运行中的任务状态可在另一入口读取。并发写入、数据库锁和配置修订冲突由核心处理。

## 9. 外部项目的功能等价接入

空白模板是创建 ICEPick Agent 的入口，不直接运行其他项目的源码，也不保证所有外部行为都能用配置表达。接入时先列出用户可观察的能力，再分别映射为 Agent 配置、Skill、MCP 工具、模型适配、应用服务或独立的外部集成。缺少对应运行能力时，应标为待实现，不能只靠提示词宣称兼容。

| 来源 | 可用空白模板承载的部分 | 需要单独适配或保留的部分 |
|---|---|---|
| 旧机器人 | 角色规则、模型选择、允许工具、任务方法、审批与委派；从模板创建独立 Agent | 工具代码封装为 MCP；历史与记忆选择性导入；定时、监视、外部渠道等另做应用能力。Telegram 身份、群管与支付不进入核心 |
| ColdBrew（工作区已有解包源码，功能尚未完整核验） | 四套目标项目中可复用的角色规则和逆向任务方法，可整理为不同 Agent 配置及 Skills；“五刃”路由中有价值的选模行为可映射为模型选择策略 | Python 预览/部署/校验/恢复流程、对 Claude/Codex/Grok/DeepSeek 配置的写入、Electron 驱动面板、环境安装及 Burp/ADB/Frida/JADX 集成属于独立工具或外部应用集成；如需保留，由受权限网关控制的 MCP 服务或应用服务承载 |

ColdBrew 的描述更像外部 Agent 配置与环境的部署工作台，不等于一套可直接嵌入 ICEPick 的 Agent 运行核心。将其任务能力放入 ICEPick 与继续修改其他 Agent 产品的配置是两项不同功能；后者需要显式选择目标、预览改动及恢复路径。不得把“破甲”提示词或对第三方产品的权限假设当作 ICEPick 的核心能力。其 Claude/Codex 项目 README 声明的是带限制的社区许可证；移植前还须核验具体代码与素材的许可、依赖和可重复功能测试。

## 10. 当前实现与缺口

当前已有 Wails 亮色界面、SQLite 会话/任务、Ollama 与 LM Studio 的本地 OpenAI Chat Completions 兼容非流式接口、多轮工具循环、取消、MCP SDK 工具调用和 Agent Skills 基础发现。已有空白 Agent 配置、Chat/Work 普通预设、可编辑配置与 Agent 切换；SQLite 迁移为旧会话归入 Chat，消息和运行记录保存 `agent_id`，运行记录保存配置版本。内置 `current_time` 通过 MCP 提供，外部 stdio MCP 服务可在本地配置中显式连接。

当前**没有** OpenAI 官方服务鉴权、Gemini/Anthropic 原生协议、流式模型接口、完整的工具权限网关、审批流程、长期记忆、上下文压缩、子 Agent 运行、CLI 或 Jev。配置界面的权限范围、审批模式、委派和上下文预算还没有执行逻辑；运行时暂时只开放配置允许的内置只读工具，外部 MCP 工具不能执行。详细进度和顺序见 [实施计划](../MIGRATION_PLAN.md)。
